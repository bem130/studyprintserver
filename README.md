# StudyPrint Server

StudyPrint Server is a local web viewer for StudyPrint indexes. It combines a Rust HTTP server with a TypeScript frontend for searching, reading, and inspecting scanned study notes.

The index format, XML specification, validator, taxonomy, and index builder live in [bem130/studyprint](https://github.com/bem130/studyprint).

## Related Projects

- [studyprintserver](https://github.com/bem130/studyprintserver): this Rust + TypeScript web viewer.
- [studyprint](https://github.com/bem130/studyprint): StudyPrint specification, validation, and deterministic index generation.
- `studyprintdata`: local data repository containing `library/**/*.xml`, scanned PNG files, and generated indexes.

## What It Does

The server reads a generated StudyPrint index and serves:

- a searchable content API,
- scanned page images from the library,
- raw XML files from the library,
- static frontend assets from `static/`.

Static assets are not embedded in the Rust binary. The frontend is built separately from TypeScript into `static/*.js`.

## Features

- Browse by broad field prefixes such as `数学/` as well as concrete paths such as `数学/確率`.
- Advanced search with plain text, regular expressions, fuzzy matching, and target scopes: title, body, meta, tags, field, date, filename, or all.
- Plain-text search highlights matching snippets in the result list.
- Result/list text prefers formula `altText`, while body rendering uses TeX through KaTeX.
- Body, XML tree, and raw XML tabs for each content item.
- Fullscreen reading for both image and body/XML views.
- Image controls for rotate, zoom, width fit, height fit, page fit, and original image opening.
- WebGL image tone processing for dark/inverted paper display, brightness, contrast, and auto normalization.
- Draggable panel splitters for filter/results width and image/body height.

## Architecture

```text
src/
  main.rs                    Rust server, DTOs, API routes, static/library serving

frontend/src/
  app.ts                     DOM wiring and rendering
  ui-state.ts                typed model/update functions and search logic
  viewer-core.ts             image layout and tone math
  xml-body-view.ts           StudyPrint XML body rendering
  generated/api-types.ts     Rust-exported API response types

static/
  app.js                     generated from TypeScript
  ui-state.js                generated from TypeScript
  viewer-core.js             generated from TypeScript
  vendor/katex.mjs           KaTeX runtime
```

Frontend state is modeled in TypeScript with explicit messages and pure update functions. Rendering derives UI from the current model instead of storing duplicate rendered state.

## Requirements

- Rust 1.82 or newer
- Node.js and npm
- A StudyPrint index generated by [studyprint](https://github.com/bem130/studyprint)

Default local paths:

- `C:\data\studyprintdata\library`
- `C:\data\studyprintdata\index`

## Build The Index First

From the `studyprint` repository:

```powershell
cargo run -p slf-index -- check `
  --library C:\data\studyprintdata\library `
  --config C:\projects\studyprint\config `
  --diagnostics-out C:\data\studyprintdata\work\diagnostics-latest.jsonl

cargo run -p slf-index -- build `
  --library C:\data\studyprintdata\library `
  --config C:\projects\studyprint\config `
  --out C:\data\studyprintdata\index `
  --deterministic `
  --overwrite
```

If XML files are moved or deleted, rebuild the index before starting the server. A stale index can point at old XML paths and prevent startup.

## Run

```powershell
cargo run
```

Open:

```text
http://127.0.0.1:7878
```

Environment variables:

| Variable | Default |
| --- | --- |
| `STUDYPRINT_INDEX_DIR` | `C:\data\studyprintdata\index` |
| `STUDYPRINT_LIBRARY_DIR` | `C:\data\studyprintdata\library` |
| `STUDYPRINT_STATIC_DIR` | `static` |
| `STUDYPRINT_BIND` | `127.0.0.1:7878` |


## Troubleshooting

`failed to load StudyPrint index`

: Rebuild the index with `slf-index build`. The usual cause is an XML file move/delete after the last index build.

Search matches formulas but the body view shows KaTeX

: This is expected. Search/list display uses XML `formula/altText`; body rendering uses `formula/tex`.

Image dark mode looks like inverted paper instead of dimmed paper

: This is intentional. The viewer inverts lightness so white paper becomes dark and dark ink becomes light while preserving color hue direction as much as possible.
